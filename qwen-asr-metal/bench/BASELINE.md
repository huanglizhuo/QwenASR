# 首次双模型实测：2026-09-19

测试机器：Apple M5 Pro、48 GB、macOS 26.7、Xcode 27.1。
参考引擎来自当前 Rust 源码 `a9325047805ca4a3776e15325678ed2f79b0a70f`，
独立 release 构建，开启原有 vDSP/Accelerate、NEON、DotProd，自动选择 15 线程。
完整文件/程序哈希、参数和逐条输出见 [JSON 快照](baselines/m5-pro-20260919.json)。

固定 20 位说话人、20 段音频，总长 **135.265 秒**。每个任务 1 轮完整预热、
7 轮实测，总计 320 次真实模型推理。下表是**整套 20 条的耗时**，不是单条延迟。

| 任务 | CPU P50 | CPU P95 | 仅作规划的 70% 时间预算 |
|---|---:|---:|---:|
| 0.6B 识别 | 5841.91 ms | 6611.90 ms | 4089.33 ms |
| 0.6B 强制对齐 | 4671.31 ms | 4777.21 ms | 3269.92 ms |

这些历史时间预算不能代替未来同轮交替运行的 CPU/GPU 比较。前一次 ASR 测量曾出现
较大系统波动；最终这次两个任务均通过 P95/P50 ≤ 1.25 的稳定性检查。所有重复运行
的输出一致。当前**没有 GPU 端到端结果，没有验证 30% 目标**。

识别准确性：

- WER：**4 / 372 = 1.0753%**。
- CER：**6 / 1542 = 0.3891%**。
- 20 条固定参考文本来自 LibriSpeech 人工转写，未使用 ASR 输出作为参考答案。
- 逐句对比结果、错误数和完整对齐输出保存在 JSON 快照中。

## 对齐发现的未决问题

当前 Rust 对齐输出中，以下两个词的结束时间超过音频时长，也超过验收检查允许的
一个 80 ms 时间类别余量：

| 样本 | 音频时长 | 预测结束 | 超出音频 |
|---|---:|---:|---:|
| `251-118436-0013` | 8225 ms | 8320 ms | 95 ms |
| `5895-34622-0004` | 4290 ms | 4640 ms | 350 ms |

这些是可观察到的边界异常，尚不能直接判定为模型错误或 Rust 实现错误。
没有人工词级边界，所以不能报告“人工对齐准确率”。工具保留全部样本、原始输出和
异常标签，继续测量其余项目，但阻塞对齐验收。需要核验原模型输出及实际音频边界，
再决定修复或建立独立人工参考；不能在 GPU 优化时静默裁剪、删样本或放宽阈值。

## Metal 实验结果

FP16 TensorOps 编译与执行通过，测试矩阵最大绝对误差为 0。
量化微基准覆盖 10 种工作负载（其中两种共用同一 shape），合计 20 个
kernel/workload 组合：W8A16 TensorOps、W8A16 SIMD GEMV、W4A16 SIMD GEMV。
每组 2 次预热、11 次实测；边界和分散坐标抽样校验最大绝对误差为 0。

详细结果见 [微基准 JSON](baselines/m5-pro-microbench-20260919.json)。
这些是使用热驻留合成权重的矩阵测试，INT4/INT8 逻辑权重相同且可精确表示；
不衡量真实模型量化误差，也不能推导整个模型的速度或准确率。
